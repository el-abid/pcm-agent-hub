01 · Vue d'ensemble

Le projet est un hub d'agents interopérable pour le PCM. Il aide un opérateur à résoudre une panne de porte palière de quai à distance, à partir de procédures documentées, puis à escalader proprement si la panne dépasse le périmètre de l'utilisateur.

Ce qui tourne où

ComposantRôleEmplacement
Passerelle A2AExpose les agents en JSON-RPC, sert les AgentCards, journaliseVotre machine, port 8787
Serveur MCP MongoDB31 outils MCP, écriture des interactions dans AtlasVotre machine, port 3000
Flows LangflowAgents, RAG Astra, critique, révisionInstance Langflow (staging ou locale)
Astra DBCollections pcm_doc et pcm_destributer_docCloud DataStax
MongoDB AtlasBase pcm_agent, collection interactionsCloud MongoDB
cloudflaredExpose les ports locaux en HTTPSVotre machine

Parcours d'une demande

  1. L'opérateur pose une question dans le Playground ou via l'API A2A.
  2. Le flow PCM Agent · Fanout envoie la question aux quatre agents en parallèle.
  3. Chaque agent interroge pcm_doc et répond avec ses sources.
  4. Les réponses sont combinées, critiquées, puis révisées.
  5. La passerelle journalise la question et la réponse dans Atlas via MCP.

Schéma du hub : fan-out A2A, quatre spécialistes, critique, révision, contacts et journalisation MCP.

Point important : ce guide fait tourner la passerelle et le serveur MCP sur votre machine, mais les agents restent dans Langflow. Si vous voulez tout héberger localement, il faut aussi installer Langflow, importer les flows et reconfigurer les URLs et les credentials.

04 · Installation

4.1 Récupérer le projet

Placez le dossier pcm-agent-hub sur la machine, puis ouvrez PowerShell dedans.

cd C:\Users\VOTRE_NOM\Documents\pcm-agent-hub
node -v
npm -v

4.2 Installer les dépendances

npm install

Les dépendances principales sont Express, dotenv, le SDK MCP, puppeteer-core (pour ce PDF) et les outils de test. Aucun build frontend n'est nécessaire.

4.3 Créer le fichier de configuration

Copy-Item .env.example .env
notepad .env

Renseignez les variables de la section 05. Le fichier .env ne doit jamais être commité.

4.4 Vérifier les tests

npm test

Attendu : 7 tests passent, dont le test anti-placeholder.

4.5 Optionnel : outils Python

py -m pip install pymongo pypdf

Utilisé par scripts/atlas-query.py et l'extraction des PDF sources.

4.6 Optionnel : MongoDB local de secours

docker run -d --name pcm-mongo -p 27017:27017 mongo:7

Utilisez ensuite mongodb://127.0.0.1:27017 comme chaîne MCP. Les données restent dans le conteneur et disparaissent si vous le supprimez.

06 · Serveur MCP MongoDB

6.1 Construire la chaîne Atlas

Le DNS SRV peut échouer selon le réseau. Utilisez les trois hôtes directs avec TLS. Le mot de passe doit être encodé : un % littéral devient %25. 

$user = 'VOTRE_UTILISATEUR'
$pass = 'VOTRE_MOT_DE_PASSE'
$enc = [uri]::EscapeDataString($pass)
$hosts = 'HOST1:27017,HOST2:27017,HOST3:27017'
$env:MDB_MCP_CONNECTION_STRING = "mongodb://${user}:${enc}@${hosts}/?authSource=admin&retryWrites=true&w=majority&tls=true"

6.2 Démarrer le serveur

npx.cmd -y mongodb-mcp-server@3.0.4 --transport http --httpHost 127.0.0.1 --httpPort 3000

Utilisez 127.0.0.1 et non localhost : cloudflared résout localhost en IPv6 et le serveur n'écoute qu'en IPv4.

6.3 Ouvrir le tunnel MCP

cloudflared tunnel --url http://127.0.0.1:3000

Notez l'URL affichée, puis ajoutez /mcp. Exemple :

https://mots-aleatoires.trycloudflare.com/mcp

6.4 Enregistrer dans Langflow

Settings → MCP Servers → mongodb-atlas-http → remplacer l'URL. Vérifiez :

GET /api/v2/mcp/servers?action_count=true
# attendu : mode=streamable_http, toolsCount=31

Si toolsCount vaut null, le tunnel ou le serveur est arrêté, ou l'URL est obsolète.

6.5 Vérifier localement

$env:MCP_URL='https://VOTRE-MCP.trycloudflare.com/mcp'
node scripts/mcp-test.js

Attendu : tools=31 et une connexion preconfigured.

6.6 Vérifier Atlas

py scripts/atlas-query.py

Le script lit pcm_agent.interactions et affiche le dernier document.

Base locale de secours : docker start pcm-mongo, puis $env:MDB_MCP_CONNECTION_STRING='mongodb://127.0.0.1:27017' et redémarrez le serveur MCP. Les tools restent les mêmes.

07 · Passerelle A2A

7.1 Démarrer

npm start

Attendu :

- orchestrator: configured
- docs-agent: configured
- equipment-agent: configured
...

7.2 Vérifier en local

Invoke-RestMethod http://localhost:8787/healthz | ConvertTo-Json -Depth 4

Les 8 agents doivent être configured: true.

7.3 Ouvrir le tunnel

cloudflared tunnel --url http://localhost:8787

Copiez l'URL dans PUBLIC_BASE_URL, puis redémarrez la passerelle :

# arrêter le processus sur 8787
Get-NetTCPConnection -LocalPort 8787 -State Listen | Select-Object -ExpandProperty OwningProcess | ForEach-Object { Stop-Process -Id $_ -Force }
npm start

7.4 Régénérer les AgentCards

npm run cards

Les fichiers agent-cards/*.json contiennent la nouvelle URL publique.

7.5 Mettre à jour l'URL dans les flows

Le flow PCM Agent · Fanout contient quatre nœuds A2A Call. Pour chacun, remplacez Hub URL par la nouvelle URL de la passerelle. Si vous utilisez encore PCM Agent · Hub, mettez aussi à jour ses nœuds A2A Client Tool.

Trois endroits à mettre à jour quand un tunnel change : .env (PUBLIC_BASE_URL ou MCP_SERVER_URL), les nœuds A2A dans Langflow, et les AgentCards via npm run cards.

8.2 Structure du fan-out

  1. Chat Input reçoit la question.
  2. Quatre A2A Call appellent Docs, Équipements, Modes dégradés et Annuaire en parallèle.
  3. Quatre Combine Text assemblent la question et les quatre réponses.
  4. Critique reçoit le texte combiné et renvoie un verdict JSON.
  5. Révision corrige la réponse.
  6. Contact Enricher restaure les numéros exacts si nécessaire.
  7. Chat Output publie la réponse finale.

8.3 Points à vérifier dans chaque flow

  • Le flow est en access_type: PUBLIC si la passerelle est en mode public.
  • L'agent a bien l'outil Astra SEARCH_DOCUMENTS sur la bonne collection.
  • Le modèle configuré supporte les outils et répond en français.
  • Le max_tokens reste bas (512 à 1536) pour tenir dans les quotas.
  • Les prompts sont dans docs/prompts/ et versionnés avec le projet.
Session Langflow : le jeton expire toutes les 20 à 30 minutes. Si les appels API renvoient ACCESS_TOKEN_EXPIRED, ouvrez un nouvel onglet /flows ou reconnectez-vous. La passerelle peut continuer à tourner.

09 · Démarrage complet

Checklist ordonnée

  1. MongoDB Atlas accessible et IP autorisée.
  2. Serveur MCP démarré sur le port 3000.
  3. Tunnel MCP ouvert, URL notée.
  4. URL MCP mise à jour dans Langflow, toolsCount=31.
  5. Passerelle démarrée sur le port 8787.
  6. Tunnel gateway ouvert, URL notée.
  7. PUBLIC_BASE_URL mise à jour, passerelle redémarrée.
  8. Les 4 nœuds A2A Call du fan-out pointent vers la nouvelle URL.
  9. npm run cards exécuté.
  10. /healthz vert, 8 agents configurés.
  11. npm test vert.
  12. npm run smoke ou test ciblé.

Commandes de la session type

# Terminal 1 : MCP
$user='...'; $pass='...'; $enc=[uri]::EscapeDataString($pass)
$hosts='HOST1:27017,HOST2:27017,HOST3:27017'
$env:MDB_MCP_CONNECTION_STRING="mongodb://${user}:${enc}@${hosts}/?authSource=admin&retryWrites=true&w=majority&tls=true"
npx.cmd -y mongodb-mcp-server@3.0.4 --transport http --httpHost 127.0.0.1 --httpPort 3000

# Terminal 2 : tunnel MCP
cloudflared tunnel --url http://127.0.0.1:3000

# Terminal 3 : passerelle
npm start

# Terminal 4 : tunnel gateway
cloudflared tunnel --url http://localhost:8787

Après avoir noté les deux URLs, mettez à jour .env et les nœuds A2A, puis :

npm run cards
Invoke-RestMethod http://localhost:8787/healthz

12.2 Sauvegarde

  • Exporter les flows Langflow (JSON) après chaque changement de prompt.
  • Sauvegarder .env dans un coffre-fort, pas dans Git.
  • Exporter la collection Atlas pcm_agent.interactions si elle sert d'audit.
  • Conserver les AgentCards générées avec la version du code.

12.3 Sécurité

La configuration de démonstration est publique : les flows sont en accès public, le tunnel MCP est en écriture et Atlas est joignable. Coupez les tunnels après la démonstration. Ne laissez jamais cette configuration exposée en production.
  • Utilisez un utilisateur Atlas dédié, limité à pcm_agent.
  • Générez un A2A_BEARER_TOKEN long et unique.
  • Ne mettez jamais l'URI Atlas ni le mot de passe dans un prompt ou un flow.
  • Repassez les flows en privé et utilisez une clé API acceptée dès que possible.
  • Fermez cloudflared et le conteneur local après usage.
  • Faites tourner les secrets après une démonstration publique.

13.4 Limites connues

  • Le quota gratuit OpenRouter est limité à 50 requêtes par jour.
  • Les modèles gratuits peuvent être lents ou rate-limités.
  • Le flow fan-out dépend de deux tunnels actifs.
  • La collection distributeur couvre le DAT, pas les pièces de porte.
  • L'assistant lit et conseille, il ne commande jamais de pièce.

13.5 Prochaines étapes

  1. Ingérer les documents des nouvelles familles de maintenance : escaliers mécaniques, portillons, éclairage, ascenseurs.
  2. Tester le hub avec des opérateurs non techniques et mesurer les pannes réellement évitées.
  3. Repasser les flows en privé, utiliser une clé API acceptée et retirer l'accès public au serveur MCP.
  4. Enregistrer la démonstration et archiver les AgentCards avec la version du code.
Principe directeur : le hub ne remplace pas l'expert. Il rend accessible ce qui est déjà documenté, il trace ce qui a été fait, et il escalade dès que la sécurité ou le périmètre l'exigent.
